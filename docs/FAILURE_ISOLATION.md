# 故障隔离与恢复

小宠物属于附加界面。0.4.1 的原则是：自身异常时停止本次实例、释放资源并记录诊断，让宿主继续工作；不在同一次加载中反复重试。

## 这次故障

头像收起功能更换了 DOM，但渲染仍访问已经删除的 `.dock`，导致 `Cannot set properties of null (setting 'hidden')`。异常从 createPet 继续抛给插件激活过程，形成用户看到的 Failed to load plugins。头像内部还有重复限定根节点的选择器，会在收起时得到空节点。

修复后保留普通收起按钮作为头像锚点不可用时的回退。布局更新不再递归安排定时器；退出时恢复宿主标志原来的 visibility 值与优先级。

## 插件内已经覆盖的边界

| 边界 | 出错后的处理 |
| --- | --- |
| 模块工厂执行 | 记录错误，返回无界面的空插件导出，避免把执行异常继续交给加载器 |
| effect 注册与初始化 | 停止初始化；已创建的宠物、观察器和监听器逐项释放 |
| 会话订阅和任务渲染 | 回调局部捕获；注销会话与消息源监听，卸载宠物 |
| 宠物事件和动画计时器 | 移除失效实例，停止帧循环，通知适配器清理其他资源 |
| MutationObserver、resize 和延迟布局 | 失败后停止监听与延迟回调，恢复被暂时隐藏的宿主标志 |
| 异步会话导航 | 处理 Promise 拒绝，不形成未处理拒绝，停止宠物实例 |
| 清理过程 | 单个清理函数抛错时，继续清理剩余资源；重复清理不重复执行 |

诊断保留在浏览器控制台，前缀为 `[mini-pet]`，包含失败阶段与异常。不覆盖 window.onerror、不吞掉其他插件的异常、不修改宿主聊天数据。插件仍与宿主共享页面和主线程，这些边界不是进程隔离。

## 插件层无法兜底的情况

脚本还没执行时的下载失败、语法错误、加载器本身故障、必需依赖解析失败，以及主线程死循环，无法由插件自己的 try/catch 完整兜底。真正保证一个插件故障时仍进入主界面，需要 dsh 宿主为可选插件提供失败后跳过、单插件停用或安全模式；这次没有修改 dsh 源码，也没有声称已完成宿主级隔离。

## 紧急恢复

在 Web 服务所在机器运行：

```sh
npm_config_ignore_scripts=true dsh plugin --profile web remove dsh-mek-mini-pet
```

随后刷新页面；如果服务仍使用旧的启动配置，重启该 Web 服务。卸载只去掉 profile 中的插件选择与依赖，保留本项目源码和浏览器偏好。安装器使用 profile 内的独立安装包；故障修复期间先在独立演示页和测试宿主验证，再打包安装。

修复完成后，确认需要恢复时再在项目目录执行 `npm run install:dsh:web`，然后重启 Web 服务并完整刷新。故障修复期间保持停用，验证通过并获得恢复指示后再装回。

## 本地验证

```sh
npm test
npm run dev
# 另一个终端，已安装 Playwright/Chromium 时：
npm run test:browser
npm run test:boot-safety
```

故障注入测试主动制造模块工厂、DOM 初始化、任务渲染、按钮回调、异步跳转与布局监听错误，检查后续测试插件执行、测试宿主按钮可操作、订阅清零和标志样式恢复。它验证插件对外的异常边界，不代替实际 dsh 页面启动验收。
